消防指令台 位置特定システム - 使い方

通報者のスマホGPSとチャットから施設を自動特定するシステム

システム概要

通報者のスマホから GPS 位置情報を取得し、チャットの発言内容から周辺施設を自動検索・地図表示するシステムです。

  • 指令台（PC） — 地図表示・チャット・施設検索を操作
  • 通報者（スマホ） — GPS送信・チャット応答
  • 接続は P2P（PeerJS/WebRTC）、サーバー不要

通常モード（実際の通報対応）

  1. 「新規セッション作成」を押す
  2. 「通報者リンクをコピー」を押して、通報者のスマホにリンクを送る（SMS・LINE等）
  3. 通報者がリンクを開くと自動でGPS位置が地図に表示される（赤い誤差円）
  4. チャットで会話しながら施設を特定。発言内容は自動でOSM検索される

試験モード（P2P接続なしで動作確認）

通報者のスマホなしで、指令台単体でシステムの動作確認ができます。
任意の位置と誤差半径を手動で設定し、チャットにキーワードを入力してPOI検索をテストできます。

  1. トップ画面で「試験モードで開始」を押す
  2. 地図上に紫のパネルが表示される。地図をクリックして通報者の仮想位置を設定
  3. スライダーで誤差半径を調整（5m〜500m）。検索範囲は「誤差 x 5」
  4. チャット欄にキーワードを入力して Enter。自動でOSM検索が実行される
試験例 位置: 向河原駅付近をクリック / 誤差: 50m（検索範囲250m）
チャット入力: セブンと居酒屋が見えます
→ 250m圏内のセブンイレブンと居酒屋がマーカー表示。両方が近接する地点がハイライトされる

試験モード中も、セッションバーの「試験モード」ボタンでパネルの表示/非表示を切り替えられます。 位置を変えたい場合は再度地図をクリックするだけです。

処理フロー全体図

チャットに入力されたテキストが、以下のパイプラインで自動処理されます。
新しいメッセージが来ると前回の検索結果は自動クリアされ、最新の結果だけが表示されます。

チャット入力 → 「セブンの横にすし屋が見えます。めんぱちの近く」
↓
辞書マッチ → 「セブン」「すし」がヒット（かな正規化: すし=スシ も同一扱い）
形態素解析 → 「めんぱち」を固有名詞として抽出（辞書にない語）
↓
Overpass API → 辞書・固有名詞とも全タグ横断検索
Nominatim → 固有名詞の読み仮名 → 漢字地名を解決（並行実行）
↓
スコアリング → 距離(40%) + テキスト一致度(60%) で総合スコア → 上位5件を表示
  1. テキスト前処理 — フィラー除去（「えーっと」「あのー」等）、句読点・空白の正規化
  2. 辞書マッチ — 約100個の登録キーワードとパターン照合。かな正規化（ひらがな/カタカナ/原文の3形式で照合）により「すし」=「スシ」等の表記揺れを吸収
  3. 形態素解析 — TinySegmenter でテキストを分割 → ストップワード（助詞・動詞・副詞等200語）除去 → 隣接する非ストップ語を結合して固有名詞を復元
  4. Overpass API 検索 — 辞書マッチ: OSMタグ検索 + ラベル名の全タグ横断検索（かなバリアント付き）を1クエリで実行。固有名詞: 全タグ横断検索 [~"."~"keyword"]
  5. Nominatim 検索（固有名詞のみ）— OSMのジオコーディングAPIで読み仮名から漢字地名を解決。Overpassと並行実行し、結果をマージ（50m以内の重複は除去）
  6. スコアリング & ランキング — 全候補に総合スコアを付け、降順ソートして上位5件のみを地図とランキングパネルに表示

検索ロジック詳細

1. 辞書マッチ検索（高精度）

「セブン」「マック」「交番」「公園」など約100個の登録キーワードに最適なOSMタグで検索します。

Overpass APIに送るクエリは2種類を1つのクエリ内で同時実行します：

  • タグ検索 — [amenity=restaurant]["name"~"寿司"] のようにOSMタグ種別で絞り込み
  • 全タグ横断検索 — ラベル名（例:「寿司屋」）のかなバリアント [~"."~"寿司屋|すしや|スシヤ"] でname, brand, operator, alt_name等すべてのタグを対象に検索。タグ種別が不正確なOSMエントリも漏れなく拾える
例: 「すし屋が見える」 辞書パターン /寿司|すし|鮨/ にマッチ
→ Overpass: [amenity~"restaurant|fast_food"]["name"~"寿司|すし|鮨|スシ|寿し"]
→ 同時に: [~"."~"寿司屋|すしや|スシヤ"] で全タグ横断検索

2. かな正規化（表記揺れ対策）

ひらがな・カタカナをUnicodeコードポイント変換で相互変換し、自動的にすべての表記形で検索します。

入力自動生成されるバリアント結果
すし屋すし屋 / スシ屋同じ検索結果
スタバスタバ / すたば同じ検索結果
カフェカフェ / かふぇ同じ検索結果
らーめんらーめん / ラーメン同じ検索結果

適用箇所: 辞書パターンマッチ、Overpassクエリ、スコア計算、固有名詞の辞書除外判定

3. 固有名詞検索（形態素解析 + Nominatim）

辞書にないキーワードは TinySegmenter（形態素解析）で自動抽出し、2つのAPIを並行実行します：

  • Overpass 全タグ横断検索 — [~"."~"keyword"] でOSMの全タグ（name, brand, operator, alt_name, 住所等）を正規表現マッチ。かなバリアントも自動生成
  • Nominatim ジオコーディング — OSM内部の読み仮名辞書を利用して、ひらがな → 漢字地名を解決
例: 「むさしこすぎ駅の近く」 形態素解析で「むさしこすぎ駅」を抽出
→ Overpass: [~"."~"むさしこすぎ駅|ムサシコスギ駅"]（かな読みタグにヒット）
→ Nominatim: 「むさしこすぎ駅」→ 武蔵小杉駅 を解決して座標を返す
→ 両方の結果をマージ（50m以内の重複は自動除去）
例: 「めんぱちが見えます」 形態素解析で「めんぱち」を抽出（辞書にない語）
→ Overpass: 全タグから "めんぱち|メンパチ" を検索
→ Nominatim: 「めんぱち」で地名検索（ヒットすれば追加）
→ name タグに「めんぱち」を含む店舗がヒット

4. 複数キーワード絞り込み

複数施設が発言に含まれると、全カテゴリが近接する地点を自動でハイライトします。

例: 「薬局とパン屋がある」 「薬局」と「パン屋」をそれぞれ検索
→ 薬局とパン屋の両方が近くにある地点を緑色の円でハイライト

スコアリング（上位5件の選出ロジック）

検索でヒットした全候補に総合スコアを付け、上位5件だけを表示します。

総合スコア = 近距離ボーナス(0-100) × 40% + テキスト一致度(0-100) × 60%

近距離ボーナス（40%配分）

通報者の位置からの距離を、GPS誤差円を基準にした段階評価で採点します。

距離スコア
誤差円内100
誤差円 x 1〜2倍80
誤差円 x 2〜3倍60
誤差円 x 3〜4倍40
誤差円 x 4〜5倍20
誤差円 x 5倍超0

テキスト一致度（60%配分）

辞書マッチ・固有名詞とも同一ロジックでスコアリングします。
POIのタグ値に検索ラベルがどれだけ一致するかを「タグ重要度 × マッチ品質」で評価します。

タグ重要度例
name1.0（最高）正式名称に一致
brand0.85ブランド名に一致
operator0.75運営者名に一致
alt_name / short_name0.7別名・略称に一致
name:* (言語別)0.65多言語名に一致
その他のタグ0.3説明文等に一致
マッチ品質倍率例
完全一致1.0「めんぱち」= name:「めんぱち」
前方一致0.9「めんぱち」= name:「めんぱち 川崎店」の先頭
含有一致0.5 + 長さ比率 x 0.3「めんぱち」が name:「居酒屋めんぱち本店」に含有

辞書マッチでテキスト一致なしの場合：50点
カテゴリタグ（shop=convenience等）のみでヒットし、POI名にラベルを含まない場合。
例: 「コンビニ」で検索 → shop=convenience のPOIがヒットしたが、名前は「セブン-イレブン」

具体例 1: 辞書マッチ（ブランド名一致） 検索語: 「セブンイレブン」(辞書) / 候補: name=「セブン-イレブン 武蔵小杉店」 / 距離: 誤差円内
テキスト = name(1.0) × 前方一致(0.9) = 90点
距離 = 100点
総合 = 100 × 0.4 + 90 × 0.6 = 94点
具体例 2: 辞書マッチ（カテゴリのみ） 検索語: 「コンビニ」(辞書) / 候補: name=「ファミリーマート」(shop=convenience) / 距離: 誤差円 x2
テキスト = 50点（POI名に「コンビニ」を含まないがカテゴリタグ一致）
距離 = 80点
総合 = 80 × 0.4 + 50 × 0.6 = 62点
具体例 3: 固有名詞 検索語: 「めんぱち」 / 候補: name=「居酒屋めんぱち本店」 / 距離: 誤差円内
テキスト = name(1.0) × 含有(0.5 + 4/9 × 0.3 = 0.63) = 63点
距離 = 100点
総合 = 100 × 0.4 + 63 × 0.6 = 78点

マーカーの見方

  • 赤い円（破線） — GPS誤差円（通報者の位置精度）
  • 黄色い円（破線） — POI検索範囲（誤差 x 5）
  • 番号付き丸ピン — スコア上位の候補地点（#1=金, #2=銀, #3=銅, #4-5=青系）
  • 緑の円（破線） — 複数キーワードが近接する地点のハイライト

マーカーをクリックするとスコア内訳（距離/テキスト）、施設名、OSMタグ情報（amenity, shop, cuisine, 住所等）が表示されます。

地図左下の候補地点パネルで施設名をクリックすると、その地点に地図を移動できます。

注意事項

  • 施設データは OpenStreetMap のボランティアデータに基づきます。登録されていない施設はヒットしません。
  • 都市部は高密度にデータが揃っていますが、地方・山間部は少ない場合があります。
  • Nominatimの読み仮名解決は、OSMデータベース内に読みが登録されている地名・施設名が対象です。
  • 新しい検索結果が出ると、前回のマーカーは自動で消去されます。
  • P2P接続はPeerJSの公開サーバーを利用しています。ネットワーク環境により接続が不安定な場合があります。
  • GPSの精度はスマホの機種・環境（屋内/屋外、天候）に依存します。
