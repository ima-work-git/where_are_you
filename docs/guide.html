消防指令台 位置特定システム - 使い方

通報者のスマホGPSとチャットから位置を自動特定するシステム

このシステムでできること

通報者のスマホからGPS位置を取得し、チャットの発言から周辺施設を自動検索して地図に表示します。 指令台と通報者はP2P（WebRTC）で直接接続するため、外部サーバーは不要です。

機能概要状態
GPS位置取得 通報者のスマホからリアルタイムにGPS座標と精度を取得し、誤差円で表示 実装済
施設キーワード検索 「セブンの横」「公園が見える」等のチャット発言から施設を自動検索。約100語の辞書＋形態素解析で対応 実装済
固有名詞検索 辞書にない店名・地名もOverpass全タグ検索＋Nominatim読み仮名解決で検索 実装済
複数キーワード絞り込み 「薬局とパン屋がある」のように複数施設が近接する地点をハイライト 実装済
スコアリング 距離(40%)＋テキスト一致度(60%)で候補を自動ランキングし上位5件を表示 実装済
住所ジオコーディング 通報者が番地号付き住所をチャットした場合に地図上に表示する機能 開発中

基本的な使い方

  1. 「新規セッション作成」を押す
  2. 「通報者リンクをコピー」を押して、通報者のスマホにリンクを送る（SMS・LINE等）
  3. 通報者がリンクを開くと自動でGPS位置が地図に表示される（赤い誤差円）
  4. チャットで会話しながら施設を特定。発言内容は自動でOSM検索される
使用例 通報者: セブンと居酒屋が見えます
→ GPS位置周辺のセブンイレブンと居酒屋を自動検索。両方が近接する地点がハイライトされる

試験モード（P2P接続なしで動作確認）

通報者のスマホなしで、指令台単体でシステムの動作確認ができます。
任意の位置と誤差半径を手動で設定し、チャットにキーワードを入力してPOI検索をテストできます。

  1. トップ画面で「試験モードで開始」を押す
  2. 地図上に紫のパネルが表示される。地図をクリックして通報者の仮想位置を設定
  3. スライダーで誤差半径を調整（5m〜500m）。検索範囲は「誤差 x 5」
  4. チャット欄にキーワードを入力して Enter。自動でOSM検索が実行される

地図の見方

表示意味
赤い円（破線） GPS誤差円 — 通報者の位置精度に応じた範囲
黄色い円（破線） POI検索範囲（GPS誤差 x 5）
番号付き丸ピン スコア上位の施設候補（#1=金, #2=銀, #3=銅, #4-5=青系）
緑の円（破線） 複数キーワードが近接する地点のハイライト

マーカーをクリックするとスコア内訳（距離/テキスト）、施設名、OSMタグ情報が表示されます。

地図左下の候補地点パネルで施設名をクリックすると、その地点にジャンプします。

処理フロー

チャットに入力されたテキストが、以下のパイプラインで自動処理されます。
新しいメッセージが来ると前回の検索結果は自動クリアされ、最新の結果だけが表示されます。

チャット入力 → 「セブンの横にすし屋が見えます。めんぱちの近く」
↓
辞書マッチ → 「セブン」「すし」がヒット（かな正規化: すし=スシ も同一扱い）
形態素解析 → 「めんぱち」を固有名詞として抽出（辞書にない語）
↓
Overpass API → 辞書キーワード・固有名詞とも全タグ横断検索
Nominatim → 固有名詞の読み仮名 → 漢字地名を解決（並行実行）
↓
スコアリング → 距離(40%) + テキスト一致度(60%) で総合スコア → 上位5件を表示
  1. テキスト前処理 — フィラー除去（「えーっと」「あのー」等）、句読点・空白の正規化
  2. 辞書マッチ — 約100個のキーワードとパターン照合。かな正規化（ひらがな/カタカナ/原文の3形式で照合）で表記揺れを吸収
  3. 形態素解析 — TinySegmenter でテキスト分割 → ストップワード除去 → 隣接語を結合して固有名詞を復元
  4. Overpass API 検索 — 辞書マッチ: OSMタグ検索 + サブタグ検索（cuisine等）+ 全タグ横断検索。固有名詞: 全タグ横断検索
  5. Nominatim 検索（固有名詞のみ）— 読み仮名から漢字地名を解決。Overpassと並行実行、50m以内の重複は除去
  6. スコアリング & ランキング — 全候補に総合スコアを付け、上位5件を地図とパネルに表示

検索ロジック詳細

辞書マッチ検索

「セブン」「マック」「交番」「公園」など約100個の登録キーワードに最適なOSMタグで検索します。 Overpass APIに送るクエリは最大3種類を1つのクエリ内で同時実行します：

  • タグ検索 — [amenity=restaurant]["name"~"寿司"] のようにOSMタグ種別で絞り込み
  • サブタグ検索 — 飲食カテゴリでは [cuisine~"udon"] 等の業種タグでも検索。名前に「うどん」を含まない「丸亀製麺」等もヒット
  • 全タグ横断検索 — ラベル名のかなバリアント [~"."~"寿司屋|すしや|スシヤ"] でname, brand, alt_name等すべてのタグを対象に検索
例: 「うどん屋が見える」 辞書パターン /うどん(?:屋)?/ にマッチ
→ タグ検索: [amenity~"restaurant|fast_food"]["name"~"うどん|饂飩"]
→ サブタグ検索: [cuisine~"udon"]（丸亀製麺等）
→ 全タグ横断: [~"."~"うどん屋|うどんや|ウドンヤ"]

かな正規化（表記揺れ対策）

ひらがな・カタカナを相互変換し、すべての表記形で検索します。

入力自動バリアント
すし屋すし屋 / スシ屋
スタバスタバ / すたば
らーめんらーめん / ラーメン

固有名詞検索（形態素解析 + Nominatim）

辞書にないキーワードは形態素解析で自動抽出し、2つのAPIを並行実行します：

  • Overpass 全タグ横断検索 — [~"."~"keyword"] でOSM全タグを正規表現マッチ
  • Nominatim — 読み仮名辞書でひらがな → 漢字地名を解決
例: 「むさしこすぎ駅の近く」 → Overpass: [~"."~"むさしこすぎ駅|ムサシコスギ駅"]
→ Nominatim: 「むさしこすぎ駅」→ 武蔵小杉駅 を解決
→ 両方の結果をマージ（50m以内の重複は除去）

複数キーワード絞り込み

複数施設が発言に含まれると、全カテゴリが近接する地点を緑色の円でハイライトします。

例: 「薬局とパン屋がある」 → 薬局とパン屋をそれぞれ検索 → 両方が近くにある地点をハイライト

スコアリング

検索ヒット全候補に総合スコアを付け、上位5件だけを地図とランキングパネルに表示します。

総合スコア = 近距離スコア(0-100) × 40% + テキストスコア(0-100) × 60%

詳しい計算ロジック・具体例は スコアリングについて をご覧ください。

住所ジオコーディング 開発中

通報者がチャットで番地号付きの住所を伝えた場合に、自動で住所を検出して地図上に表示する機能です。
現在開発中のため、正しく動作しない場合があります。

  • 対応予定パターン: ○○市○○町1-2-3 / ○○市○○1丁目2番3号 / ○○市○○1741 等
  • 全角数字・各種ハイフンは自動で半角に変換
  • Nominatim（OSMジオコーディングAPI）で座標に変換し、マゼンタ色のマーカー+範囲矩形で表示予定

注意事項

  • 施設データは OpenStreetMap のボランティアデータに基づきます。登録されていない施設はヒットしません
  • 都市部は高密度にデータが揃っていますが、地方・山間部は少ない場合があります
  • Nominatimの読み仮名解決は、OSMデータベース内に読みが登録されている地名・施設名が対象です
  • 新しい検索結果が出ると、前回のマーカーは自動で消去されます
  • P2P接続はPeerJSの公開サーバーを利用しています。ネットワーク環境により接続が不安定な場合があります
  • GPSの精度はスマホの機種・環境（屋内/屋外、天候）に依存します
